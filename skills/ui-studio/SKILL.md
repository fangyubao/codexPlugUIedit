---
name: ui-studio
description: Open the UI Studio visual editor for drag-and-drop UI design and shared agent edits. Inspect existing UI frameworks, edit supported Qt .ui forms, and generate Qt, Tkinter, and LVGL code. Use for visual UI authoring, not generic application automation.
---

Use this plugin's tools to keep manual edits and agent edits in the same live document.

1. Projects can be MCU LVGL, desktop/Linux LVGL, Qt Widgets/Quick, PySide/PyQt, OSD or unknown frameworks. Call `inspect_ui_project` with the path. Read framework/version evidence, MCU/host/mixed targets, build systems, conflicts and scan omissions. Detection is not editability. Keep LVGL and Qt major versions and Python bindings; do not replace the original framework with Qt/web merely to produce a canvas. MCU UI host preview does not imply complete board emulation.
2. Call `open_ui_editor` in default `mode: auto` with that path and optionally a specific project-relative `.ui`. It resumes an existing Studio design, imports an unambiguous supported form, or returns `view: project` containing an inspection report. The report is NOT an imported or editable UI; state which adapter stages are missing. `mode: new` and `demo: true` are only for an explicitly requested independent new design or sample. Never silently replace an unsupported imported project with a blank/sample design.
3. The tool returns a panel resource and a local `editorUrl`. If the host does not render MCP Apps, open that URL in Codex's right browser panel using the available `open_in_codex` tool. Generic designs use a browser approximation. WatchX LVGL 6.1.2 shows its actual static native rendering with selectable source-mapped objects.
4. Before each edit, call `get_ui_document`. Its snapshot includes `revision`, `selectedIds`, widgets, warnings and source restrictions. Send `apply_ui_operations` with that exact revision. The user's selection is part of the shared snapshot. On revision conflict, re-read and reconsider the intended change; never overwrite the user's changes with a stale document.
5. Operations support `add` with a `node`, `update` with `id`/`changes`, `remove` with `ids`, `canvas` with `changes`, and `reorder` with `ids`. See the tool schemas. The UI and tools use the same validation and undo history. Use the user's actual selected objects and exact requested coordinates.
6. `export_ui_project` writes to `.ui-designer/exports/`. It never overwrites the imported application. Qt imports retain unknown XML, connections and custom widget declarations in an exported copy; layout-managed forms are inspection-only in v0.1. Exported source is generated UI code; event/business logic must be connected separately.

New designs export to `qt-ui`, `pyside6`, `qt-cpp`, `tkinter`, or `lvgl`. LVGL targets v9 and needs the user's platform/display driver and configured fonts; the plugin does not claim STM32 emulation. Arbitrary Python/C/C++ round trips, QML, interactive runtime streams and runtime inspector bridges remain future adapters.

For real Qt appearance of a new design, call `render_ui_preview` with its latest revision. This creates a project-local virtual environment and installs PySide6 if missing, then renders generated widgets to PNG in the background. Use `get_ui_preview(jobId)` to retrieve status and the local image path; do not repeatedly request base64 images in model context. The editor's preview button shows that same PNG. This is a static native render, not an interactive running application. Imported arbitrary .ui/project execution is deliberately not part of this preview adapter because custom widgets and resources need project-specific setup.

For dependencies, use `inspect_ui_project`'s plan and the project manifests. The `pyside6` export includes `requirements.txt` and is suitable for a project-local virtual environment. Native Qt rendering prepares this environment automatically; other framework runtimes still need explicit adapter work. Install missing packages only for an adapter/runtime actually being used. Do not run an imported project or install every detected framework merely to inspect it. The editor itself requires Node 20+ and `npm ci` / `npm run build` at the plugin root; it needs no cloud API key.

The product requirement is arbitrary UI project intake with adapters, including MCU targets. Report import, preview, edit and original-source writeback independently. WatchX LVGL 6.1.2 has a specific seven-page adapter: DialPlate, MainMenu, TimeCfg, Backlight, StopWatch, Altitude, About. open_ui_editor automatically selects it for the matching structure; optional page switches pages. It builds original LVGL/resources with hardware stubs, exposes mapped existing objects, re-renders edits natively, and save_ui_source(sessionId, revision) writes backed-up GBK page integration plus generated LVGL 6 overrides. It does not add/delete controls, change parentage, replace fonts/images, support Game, or emulate hardware. Never export this imported project as LVGL 9. Source/header external changes block writeback. Dynamic callbacks/animation/layout may overwrite Setup overrides; state this limit for affected edits. Native host validation is not Keil firmware or real-board validation. Other frameworks still lack original-source writeback; new code export must never be described as it. A future adapter must preserve source locations, layout constraints, resources and event/business logic and pass an actual edit/save/reopen/build cycle. See the plugin root's PRODUCT_REQUIREMENTS.md when extending adapters.

The agent is Codex in the current conversation. There is no separate embedded AI API. In a compatible MCP App, the selected-object request button sends a user-authored message via the host bridge; in browser fallback it copies a prompt for the user to paste into this chat.

Experimental DWIN inspection is a separate CLI, not an open_ui_editor adapter: run scripts/inspect-dwin.mjs on an extracted project containing DWprj.hmi, TFT page files and DWIN_SET. It produces report.json and inspector.html for read-only page/control/VP inspection. scripts/serve-dwin-inspection.mjs serves that view locally. Do not claim drag editing, source writeback, compiled download regeneration or hardware simulation for this path. Keep user project resources and generated reports out of the plugin source repository.
